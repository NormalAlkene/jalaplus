# 提示词记录

本文整理开发过程中影响项目方向的关键提示词。环境检查、命令调试、重复的 UI 微调，以及已经废弃的中间方案已省略；提示词主体尽量保留原话。

## 1. 初始任务

> 网站插件或脚本开发任务
>
> ## 背景
>
> jala.tools 是一个日语学习网站，它有 JLPT 历年真题在线做题功能。然而，却没有导出错题或总体评分功能。我希望开发一个项目，包含：
> 1. 一款 firefox 插件或 tampermonkey 脚本（请首先分析哪个更合适），叫做 JaLaPlus，用来导出一套试题作答情况，供我与 LLM 稍后分析。
> 2. 一个 CLI 工具，叫做 JaLaQuery，用来提供一个友好接口对导出的记录进行查询与分析，可分析试题的作答情况、正确率等统计数据。用 rust 开发。并生成配套的 skill，供 LLM 使用。
>
> ## 功能要求
>
> ### 浏览器插件或脚本
>
> 用来进行题目收藏、作答情况导出、本地存储操作等任务。
>
> 插件内部需要包含一个“收藏集”类似的存储区域，用于按试卷分开存储整理。
>
> - 首先，注入浮动按钮“添加到收藏集”（呈现为一个简洁的加号图标，按钮为圆形）
>   * 在具体一道题的页面（如 https://jala.tools/zh/jlpt/n2/2020-12/vocabulary/word-formation/1 ），可将当前作答情况作为快照存储，信息包含：用户作答、正确答案、网站提供的答案解析、听力文本（如果是听力题）、作答记录。若用户当前未作答，则不记录当前的用户作答，并以简单的 toast 提醒用户。
>     - 网站本身会记录用户的作答记录，但只显示正误计数，不展示每次作答情况。我需要你在开发前调查一下，每次作答情况是否被网站存储且可由插件访问？若是，则存储详细记录；若否，则只要数量即可。顺便调查它是存储在本地还是服务器。
>   * 在一套试卷整体页面（如 https://jala.tools/zh/jlpt/n2/2020-12 ）可逐题抓取题干、作答情况、答案解析（若可以读取到）。在一次作为一套试卷整理添加的记录，有着相同的保存 id，可方便地按照抓取批次整理管理。
> - 其次，注入浮动按钮“查看收藏集”，在当前页面显示一个 popup。
>   * 点击后，默认按照试卷查看，当前试卷展开，其他折叠。用户可以切换为按题型查看。
>   * 用户可导出作答情况，导出范围可选：单道题、多道题、一整套试卷、多套试卷、一个题型、多个题型。
>   * 用户可对某道题的某次记录进行删除，也可多选删除、选择一次抓取的记录（利用前述的相同保存 id）进行删除。
>   * 展示时，以每道题为准，前述的保存 id 不作为展示分类依据，仅方便选择。
> - 第三，注入按钮“操作存储”
>   * 点击后，用户可查看网站在本地存储了哪些数据并进行管理。
>
> ### CLI 工具
>
> 用来提供一个友好接口对导出的记录进行 query。
>
> - 可对一套试题根据答案阅卷判分。按照 JLPT 标准（由于尺度得点等算法未公开，只能根据题目给每道题固定分值）来标定成绩。
> - 可查询每道题的作答记录。
> - 可查询错题与用户答案并输出参考答案解析。
> - 可跨试卷进行对比分析。
> - 可以按实际情况增加一些你认为重要的功能。
>
> API 接口尽量设计得简洁并易于 Agent 使用，让 Agent 在尽量少的 tool call 请求下高效获取信息。另外最好格式化地节省 token，提升效率。
>
> 另外，生成一份对应的 skill。并告诉我如何安装。
>
> ## 细节要求
>
> - 先写 README.md。
> - 这是一个自用的小项目，UI 界面语言为中文。CLI 交互语言也为中文。
> - 作用域仅为 jala.tools/*/jlpt/** （如 jala.tools/zh/jlpt/2020-12/vocabulary/word-formation/1）
> - 操作逻辑要简单顺畅。
> - 设计上，图标用 svg，设计风格简约扁平化，走 Material Design 风格，仅支持浅色模式即可。
> - 页面上的按钮浮动在右侧偏下方的位置，圆形。
> - 导出格式为 JSON。
> - 所有文本说人话是最重要的，语言简洁平实朴素正式，禁止自造术语或自造缩写。
> - 遵循 AGENTS.md 的约定。
>
> ## 注意
>
> - 网站可能有 CloudFlare 防火墙，若不能访问，请告诉我。
> - 由于网站设置，答案解析与听力文本默认为登录后查看，但是这似乎更多是前端限制，将遮挡的 div 移除即可查看（此时可能不全）。我可以提供我在浏览器中本网站的 cookie。若需要，请告诉我如何操作。
> - 由于你运行在沙箱中，firefox 可能不能正常工作。若出现无法正常工作的情况，请在测试环节告诉我详细的测试步骤与需要的反馈。
> - 若当前环境缺少必要的依赖，或工具无法运行，请务必中止任务并告诉我，我来手动解决。
> - 我对浏览器扩展开发所用的工具链不是很熟悉。请用当前最流行最合适的。若环境中没有，请告诉我，由我来安装。

> ## 功能需求

>
> ## 问题
> - 为什么选择了油猴脚本而非浏览器插件？说说你的技术考量。
> - 为什么是单脚本文件而非需要编译或合并的脚本？单脚本固然易于使用，但是我比较担心的是单文件脚本是否会不利于维护，虽然维护主要应该是交给 Agent。说说你的考量。
> - jalaquery 为什么设计成有状态的？引入一个额外的状态存储（默认 $XDG_DATA_HOME/jalaquery/store.json 的那个）有什么明显优势吗？首先，有什么数据不能每次都从油猴脚本导出的 json 中读取，而要有状态？其次，你应该能够从 system prompt 中知道，当前沙箱环境下的 $HOME 本身是一个 session 级别的 tmpfs，会话退出即销毁。请阐述你设想的使用场景。我的场景是在同一个 workdir 下每次导出一套试卷的 json 让 agent 不断分析。
> - 考虑我的功能需求之后，我们现在采集的数据有三种：一是直接抓取整套试卷，二是抓取单道题数据，三是连续作答数据。这三者包含的字段并不相同，请说说你打算如何优雅设计存储格式，以及 jalaquery 中如何优雅处理。
> - 我导出了一套之前作答的试卷，文件在 temp/jalaplus-n2-2020-12-2026-10-20.json，请尝试读取并分析，告诉我能够分析哪些数据，对 Agent 分析我的水平与给出学习建议有何帮助？

## 5. 方案细化

> 细化方案：
> 1. 你说“IndexedDB 作为记录的唯一存储，localStorage 只保留会话/界面状态。”，会话状态是否应该是在 sessionStorage？请为存储的所有各自选择合适的位置。
> 2. 我发现现在的收藏集管理有一个小 bug：当只有第一条外层记录展开时，无法折叠。请一并修复。
> 3. 连续答题应当注意显示与内部状态同步，应当能够应对一定程度的状况（如点击下一题、重新加载、标签页卸载后重新加载、返回上一级试卷界面再进入另一题等）而不出现不一致状态。
> 4. IndexedDB 是否提供了一个标准的 API 来查询配额与当前用量？如果没有标准 API 或无法精确测量，则不需要空间占用预警功能。
> 5. 所有 API 应当使用标准 API，不得 hack 或使用各种非标准方法。若有特别难以实现的功能，请在 chat 中明确标注。
> 6. Tampermonkey 在第 6 行：`// @include      /^https:\/\/jala\.tools\/[a-z]{2}\/jlpt(?:\/|$)/` 给出警告：`eslint: userscripts/avoid-regexp-include - Using a regular expresion at '@include' can cause performance issues. Use a regular @include or @match instead.`
>
> 开始按计划执行，记得在合适的时间 commit。
